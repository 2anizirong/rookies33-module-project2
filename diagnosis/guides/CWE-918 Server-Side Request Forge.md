# CWE-918: Server-Side Request Forgery

## 정의

웹 애플리케이션이 사용자가 입력한 URL을 충분히 검증하지 않고
서버 측에서 요청하는 취약점이다.

## 주요 발생 원인

- 사용자 입력 URL을 검증하지 않음
- 목적지 IP 주소를 정규화하지 않음
- Loopback 및 사설 IP 범위를 차단하지 않음
- 리다이렉트 이후의 최종 목적지를 검증하지 않음
- 허용되지 않은 URL 스킴을 처리함

## 주요 영향

- 내부 서비스 접근
- 내부 포트 탐색
- 방화벽 및 접근통제 우회
- 클라우드 메타데이터 접근
- 내부 정보 및 인증정보 노출

## 탐지 조건

다음 조건이 확인되면 SSRF 가능성이 있다.

1. 사용자가 URL 또는 호스트를 제어할 수 있다.
2. 서버가 입력된 주소로 요청을 전송한다.
3. Loopback, 사설망 또는 메타데이터 주소에 접근할 수 있다.
4. 응답 내용, 상태 코드, 응답 시간 또는 외부 콜백 변화가 확인된다.

## 대응 방안

- 요청 가능한 목적지를 허용목록으로 제한한다.
- DNS 해석 후 실제 IP 주소를 검사한다.
- Loopback, 사설망, 링크 로컬 주소를 차단한다.
- 리다이렉트 이후의 최종 목적지를 다시 검증한다.
- HTTP와 HTTPS처럼 필요한 프로토콜만 허용한다.
